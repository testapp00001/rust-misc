# Solution 02: Set Up Prometheus and Grafana with node_exporter

## Project Structure

```
prometheus-lab/
  docker-compose.yml
  prometheus/
    prometheus.yml
  grafana/
    provisioning/
      datasources/
        prometheus.yml
```

## Prometheus Configuration

```yaml
# prometheus/prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'node-exporter'
    static_configs:
      - targets: ['node-exporter:9100']
```

## Grafana Datasource Provisioning

```yaml
# grafana/provisioning/datasources/prometheus.yml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: false
```

## Docker Compose File

```yaml
# docker-compose.yml
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.retention.time=7d'
      - '--web.enable-lifecycle'
    restart: unless-stopped

  grafana:
    image: grafana/grafana:latest
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
    volumes:
      - ./grafana/provisioning:/etc/grafana/provisioning
    depends_on:
      - prometheus
    restart: unless-stopped

  node-exporter:
    image: prom/node-exporter:latest
    ports:
      - "9100:9100"
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /:/rootfs:ro
    command:
      - '--path.procfs=/host/proc'
      - '--path.sysfs=/host/sys'
      - '--path.rootfs=/rootfs'
    restart: unless-stopped
```

## Grafana Dashboard Queries

Panel 1 -- CPU Usage (Stat panel):

```promql
100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

Panel 2 -- Memory Usage (Gauge panel):

```promql
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100
```

Panel 3 -- Disk Usage (Gauge panel):

```promql
(1 - node_filesystem_avail_bytes{fstype!="tmpfs",mountpoint="/"} / node_filesystem_size_bytes{fstype!="tmpfs",mountpoint="/"}) * 100
```

Panel 4 -- Network Received (Time series panel):

```promql
rate(node_network_receive_bytes_total{device="eth0"}[5m])
```

## Why It Works

### Service Discovery in Docker Compose

Docker Compose creates a default bridge network and registers each service
by its name. When Prometheus references `node-exporter:9100`, Docker's
built-in DNS resolves `node-exporter` to the container's IP address. This
is why you use service names, not `localhost`, for cross-container
communication.

### Prometheus Pull Model

Prometheus scrapes (pulls) metrics from targets at the configured
`scrape_interval`. Each target exposes an HTTP endpoint (typically `/metrics`)
that returns metrics in Prometheus text format. The `up` metric is
automatically generated by Prometheus -- it is `1` when the scrape succeeds
and `0` when it fails.

### Grafana Provisioning

Grafana provisioning is a mechanism to pre-configure data sources and
dashboards without manual UI interaction. The YAML files in
`/etc/grafana/provisioning/datasources/` are read on startup and create the
data sources automatically. The `isDefault: true` flag makes Prometheus the
default data source for all new panels.

### node_exporter Volume Mounts

node_exporter reads host metrics from `/proc`, `/sys`, and the root
filesystem. Inside a container, these paths refer to the container's own
virtual filesystem, not the host's. The volume mounts (`/proc:/host/proc:ro`,
etc.) expose the host's filesystem inside the container. The command-line
flags (`--path.procfs=/host/proc`, etc.) tell node_exporter where to find
the host's data.

## Verification

```bash
# Check all containers are running
docker compose ps
# Expected: all three services show "Up"

# Check Prometheus targets
curl -s http://localhost:9090/api/v1/targets | python3 -m json.tool
# Expected: both targets show "health": "up"

# Query a metric
curl -s 'http://localhost:9090/api/v1/query?query=up' | python3 -m json.tool
# Expected: two series, both with value 1

# Check Grafana
curl -s http://localhost:3000/api/health
# Expected: {"commit":"...","database":"ok","version":"..."}
```

## Common Mistakes

- **Using `localhost` in Prometheus targets for other containers.**
  `localhost` inside the Prometheus container refers to the Prometheus
  process itself, not other containers. Use Docker Compose service names.

- **Forgetting `--web.enable-lifecycle`.** Without this flag, the
  `/-/reload` endpoint does not work, and you must restart Prometheus to
  pick up configuration changes.

- **Not mounting node_exporter volumes.** Without the `/proc`, `/sys`, and
  rootfs mounts, node_exporter reports metrics about the container itself
  (which is nearly empty), not the host.

- **Grafana datasource not provisioning.** If the YAML file has a syntax
  error or is in the wrong directory, Grafana silently skips it. Check
  Grafana logs with `docker compose logs grafana`.

- **Prometheus config syntax error.** A single YAML indentation error causes
  Prometheus to fail to start. Validate with
  `docker compose logs prometheus` and look for `msg="Error loading config"`.

- **Forgetting `depends_on` for Grafana.** Without it, Grafana may start
  before Prometheus and fail to connect. `depends_on` ensures Prometheus
  starts first, though it does not guarantee Prometheus is ready.
