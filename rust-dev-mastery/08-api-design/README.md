# Module 8: API Design

Designing robust, ergonomic Rust APIs. Covers public API surface area, trait-based
design, generics vs dynamic dispatch, versioning, backward compatibility, error
types, documentation, and crate publishing.

## Lesson Index

| # | File | Topic |
|---|------|-------|
| 1 | `p01_public_api_design.rs` | API surface area, pub(crate), sealing traits, API evolution principles |
| 2 | `p02_trait_based_apis.rs` | Designing with traits, object safety, trait bounds, associated types |
| 3 | `p03_generics_vs_dyn.rs` | Static vs dynamic dispatch, monomorphization cost, when to use each |
| 4 | `p04_api_versioning.rs` | SemVer in Rust, breaking changes, deprecation, migration guides |
| 5 | `p05_backward_compatibility.rs` | Non-breaking additions, default trait methods, extension traits |
| 6 | `p06_builder_for_apis.rs` | Configuration builders, request/response builders, fluent APIs |
| 7 | `p07_error_in_apis.rs` | Error types as API contract, error documentation, error compatibility |
| 8 | `p08_documentation.rs` | Doc comments, rustdoc, examples in docs, feature-gated docs, doc tests |
| 9 | `p09_crate_publishing.rs` | crates.io publishing, metadata, categories, keywords, README |
| 10 | `p10_api_review.rs` | API review checklist, common pitfalls, ergonomic APIs, API design principles |
